# Skill: ship

## What you do

Final step. Verify is PASS, code is green, time to ship as a reviewable PR.

## How

1. **Gate**: read `docs/features/<slug>/verify-report.md`. If "Overall: PASS" not present
   -> refuse:
   ```
   [NO] Cannot ship — verify report not PASS. Run /verify first.
   ```

2. **Update CHANGELOG.md** at repo root:
   ```markdown
   ## Unreleased
   
   ### Added
   - **<feature title>** — <one-line summary from spec §1>. (<slug>)
   ```
   
   If `## Unreleased` doesn't exist -> create it.
   If `### Added` not in `## Unreleased` -> create it.

3. **Run smoke check**:
   - `python smoke_check.py` (or project equivalent from AGENTS.md)
   - `python smoke_check.py` (repo smoke test; skip if project has no tests/ folder)
   - If anything fails -> STOP, report, don't proceed

4. **Stage + commit**:
   - `git add` ONLY the files touched in this feature (from tasks.md)
   - Plus CHANGELOG.md
   - Plus the `docs/features/<slug>/` folder
   - `git commit -m "feat(<slug>): <spec §1 one-liner>"`

5. **Push + PR**:
   - Branch name: `feature/<slug>`
   - If not already on this branch, run `git checkout -b feature/<slug>` first.
   - `git push -u origin feature/<slug>`
   - `gh pr create --title "feat(<slug>): <one-liner>" --body "<auto-generated from spec.md and verify-report.md>"`
   - PR body template:
     ```markdown
     ## Summary
     <spec §1 first paragraph>
     
     ## Acceptance criteria
     - [x] AC §5 happy-1 — PASS (per verify-report.md)
     - [x] AC §5 error-1 — PASS
     - ...
     
     ## Verification
     See `docs/features/<slug>/verify-report.md` for adversarial review findings.
     
     ## Out of scope
     <spec §3>
     
     ## Open questions
     <spec §6>
     ```

6. **Handoff**:
   ```
   [OK] Shipped — PR opened at <URL>
   📋 CHANGELOG.md updated
   ⏸  Stopped before merge (human review required)
   ```

## What you DON'T do

- Don't auto-merge. Ever. The PR is the human gate.
- Don't include unrelated files in the commit. Be surgical.
- Don't squash commits unless project conventions say so.
- Don't tag a release. That's a separate `release` skill (not in SDD-lite).

## Anti-patterns to catch

- User asks "can you auto-merge?" -> no, that's a different team's call. The PR is where
  ownership transfers from agent to human.
- Smoke check fails but you want to ship anyway -> STOP. Smoke check is the floor.
- PR body that just says "see spec.md" -> expand. PR is the reader's first artifact.
